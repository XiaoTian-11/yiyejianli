# 壹页简历 — 国内轻量服务器部署

> **方案**：一台国内云服务器同时承载 **自托管 Supabase + 壹页简历 Web 服务**，后续其他产品（如二次元拼团平台）可继续复用同一台服务器与同一套 nginx 架构。
> **适用**：面向中国大陆用户。解决官方 Supabase 在境内 2~4s 高延迟/超时问题，延迟可降到 20~40ms。
> **成本**：软件全部免费开源；唯一支出是一台轻量服务器（2核8G 活动价约 ¥100~200/年首年）。

## 1. 架构总览

```
用户浏览器
   │ HTTPS
   ▼
resume.xnkun.com ──► Nginx (80/443) ──┬──► 壹页简历容器 (127.0.0.1:3000)
                                      │
                                      └──► 未来产品A容器 (127.0.0.1:3001)…
                                      │
                                      └──► Supabase Kong 网关 (127.0.0.1:8080)
                                             ├─ PostgREST (REST API / RLS)
                                             ├─ GoTrue (邮箱密码认证)
                                             └─ PostgreSQL（users / orders 表）
```

- 所有服务跑在同一台服务器，端口只绑定 `127.0.0.1`，仅 Nginx 对外
- Supabase 只启用 **Postgres + GoTrue + PostgREST + Kong**（项目用不到 Realtime/Storage/Edge Functions，精简掉可省 1GB+ 内存）
- 数据库与 Web 各用独立容器、独立数据卷，互不干扰

## 2. 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| 域名 | xnkun.com 已注册 | 需能解析子域名 `resume.xnkun.com` |
| **ICP 备案** | **必做** | 大陆服务器绑定域名必须备案；**微信支付回调强制要求已备案域名**。云厂商免费代办，周期约 1~3 周，**建议现在就先提交备案**，与后面步骤并行 |
| 服务器 | 腾讯云/阿里云轻量应用服务器 **2核8G** | Ubuntu 22.04 或 Debian 12，带宽 ≥3M。2核4G 跑精简版也能跑但余量小，拼团平台要共用则选 8G |
| 安全组/防火墙 | 放行 `22/80/443` | 云厂商控制台的「防火墙」或「安全组」中放行；3000/8080 等内部端口**不**对外放行 |
| 微信支付商户号 | 已开通 | 见 §11，可先用 `PAYMENT_PROVIDER=mock` 跑通全流程再接入 |

> ⚠️ **备案必须先行**：微信支付配置 `notify_url` 校验域名是否备案，未备案时支付回调直接配不上。服务器可以提前买、提前部署，但支付正式接入要等备案完成。

## 3. 服务器初始化

以下命令在服务器上执行（SSH 登录）。

### 3.1 系统更新

```bash
sudo apt update && sudo apt upgrade -y
```

### 3.2 安装 Docker + Compose 插件

```bash
# 官方一键安装脚本（若国内拉取失败见下方替代）
curl -fsSL https://get.docker.com | sudo sh

# 启用当前用户使用 docker 免 sudo（重开终端生效）
sudo usermod -aG docker $USER
newgrp docker
```

### 3.3 配置 Docker 国内镜像加速（关键，否则拉 Supabase 镜像极慢）

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://dockerproxy.net"
  ]
}
EOF
sudo systemctl restart docker
```

验证：`docker info | grep -A5 "Registry Mirrors"` 能看到镜像地址。

> 若加速器失效，用**轩辕镜像**等第三方加速：`docker pull docker.xuanyuan.run/镜像名`（拉取后自行 re-tag）。多备几个加速器轮换。

## 4. 生成 Supabase 密钥

自托管 Supabase 需要 4 个密钥：数据库密码、JWT 签名密钥、anon key、service_role key。其中 **anon / service_role 是 JWT**，由 JWT_SECRET 签名。

在本地（或服务器）用 Node 一行生成：

```bash
node -e "
const c = require('crypto');
const secret = c.randomBytes(64).toString('hex');
const iat = Math.floor(Date.now()/1000);
const b64 = o => Buffer.from(JSON.stringify(o)).toString('base64url');
const sig = (h,p) => c.createHmac('sha256', secret).update(h+'.'+p).digest('base64url');
const mk = role => { const h=b64({alg:'HS256',typ:'JWT'}); const p=b64({role,iss:'supabase',iat}); return h+'.'+p+'.'+sig(h,p); };
console.log('POSTGRES_PASSWORD=' + c.randomBytes(24).toString('base64'));
console.log('JWT_SECRET=' + secret);
console.log('ANON_KEY=' + mk('anon'));
console.log('SERVICE_ROLE_KEY=' + mk('service_role'));
"
```

输出示例（请务必复制保存，后面两处都要用）：

```
POSTGRES_PASSWORD=xxxxxxxx
JWT_SECRET=xxxxxxxx（64字节hex）
ANON_KEY=eyJhbGciOiJIUzI1NiIs...（JWT）
SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIs...（JWT）
```

> 🔒 **SERVICE_ROLE_KEY 等同数据库 root 权限**，只允许填入服务器端 `.env`，**绝不能出现在前端**。

## 5. 部署自托管 Supabase

### 5.1 克隆官方 Docker 模板

```bash
cd /opt
# 国内 git clone 慢可加代理：git clone --depth 1 https://ghproxy.com/https://github.com/supabase/supabase
git clone --depth 1 https://github.com/supabase/supabase.git
cd /opt/supabase/docker
cp .env.example .env
```

### 5.2 编辑 `.env`（只需改这几项）

```bash
nano .env
```

```ini
# ── 数据库 ──
POSTGRES_PASSWORD=用上面生成的

# ── JWT / API 密钥 ──
JWT_SECRET=用上面生成的
ANON_KEY=用上面生成的
SERVICE_ROLE_KEY=用上面生成的

# ── 对外访问地址（改成本域名字符串，含端口）──
SITE_URL=https://resume.xnkun.com
API_EXTERNAL_URL=https://resume.xnkun.com
SUPABASE_PUBLIC_URL=https://resume.xnkun.com

# ── 注册行为：跳过邮箱验证，注册即登录（与云端项目行为一致）──
GOTRUE_MAILER_AUTOCONFIRM=true

# ── 管理面板（仅本机访问，可不改）──
DASHBOARD_USERNAME=admin
DASHBOARD_PASSWORD=你的Studio密码
```

> 若域名还没备案/没配好 HTTPS，`SITE_URL` 可先用 `http://服务器公网IP:8080` 临时联调，域名就绪后改回。

### 5.3 精简：停用用不到的服务（省 ~1GB 内存）

编辑同目录 `docker-compose.yml`，把以下服务**整段注释掉或删除**（壹页简历不需要）：

`studio`（管理面板）、`imgproxy`、`meta`、`realtime`、`storage-api`、`analytics`、`logflare`、`vector`、`supabase-cli`

只保留：`db`、`kong`、`auth`、`rest`，以及它们依赖的 `edge-runtime`（如需可删）。

> 提示：Studio 删了之后无法网页管理数据库，本清单 §8 用 `psql` 命令代替，同样方便。

### 5.4 启动

```bash
docker compose up -d
```

### 5.5 验证

```bash
docker compose ps          # 4 个服务都是 running / healthy
curl -s http://127.0.0.1:8080/auth/v1/health | head
# 期望出现 {"status":"ok"} 相关字样
```

## 6. 部署壹页简历

### 6.1 上传项目到服务器

```bash
# 本地打包（不含 node_modules / dist / .env）
cd <项目目录>
zip -r yiyejianli.zip . -x "node_modules/*" -x "dist/*" -x ".git/*"

# 上传（或用 WinSCP / FileZilla）
scp yiyejianli.zip root@<服务器IP>:/opt/
```

服务器上解压：

```bash
cd /opt && unzip yiyejianli.zip -d yiyejianli
cd /opt/yiyejianli
```

### 6.2 配置生产环境变量

```bash
cp .env.example .env
nano .env
```

关键变量指向**自托管的 Supabase**（IP 是本机，走 Kong 8080；也可用 `http://kong:8000` 走 Docker 内网，详见下方说明）：

```ini
# 自托管 Supabase 的 API 入口（域名就绪后换成 https://resume.xnkun.com）
VITE_SUPABASE_URL="http://127.0.0.1:8080"
VITE_SUPABASE_ANON_KEY="上面生成的 ANON_KEY"
SUPABASE_SERVICE_ROLE_KEY="上面生成的 SERVICE_ROLE_KEY"

# 支付先用模拟模式跑通
PAYMENT_PROVIDER="mock"

# AI 翻译
DEEPSEEK_API_KEY="你的 DeepSeek key"

# 对外回调地址（域名就绪后改）
APP_URL="https://resume.xnkun.com"
```

> ⚠️ `VITE_SUPABASE_URL` 会被打包进前端 bundle，**发布后不要随便改**（改了要重新 build 镜像）。域名就绪后再构建正式版。

### 6.3 构建并启动容器

```bash
docker compose up -d --build
```

- 前端 `VITE_*` 从 `.env` 自动注入 build args 打进 bundle
- 运行时 secret（service_role、DeepSeek、微信）通过 `env_file: .env` 注入容器，不进前端产物
- 端口绑定 `127.0.0.1:3000`，仅本机 Nginx 可达

验证：

```bash
docker compose ps
curl -s http://127.0.0.1:3000/api/health
# {"status":"ok",...}
```

## 7. Nginx 子域名反代 + HTTPS

### 7.1 安装 Nginx + certbot

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

### 7.2 配置子域名站点

```bash
sudo nano /etc/nginx/sites-available/resume.xnkun.com
```

```nginx
server {
    listen 80;
    server_name resume.xnkun.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;   # AI 翻译 / 支付轮询可能较久
    }
}
```

启用并重载：

```bash
sudo ln -s /etc/nginx/sites-available/resume.xnkun.com /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### 7.3 申请 HTTPS 证书（自动续期）

```bash
# 前提：域名解析已生效（见下），且安全组已放行 80/443
sudo certbot --nginx -d resume.xnkun.com
sudo certbot renew --dry-run   # 验证自动续期
```

> **DNS 配置**：到 xnkun.com 的域名商控制台添加记录 `resume` → **CNAME 指向服务器**（腾讯云/阿里云服务器可直接填公网 IP 做 A 记录）。

### 7.4 域名就绪后回炉构建正式版

因为 `VITE_SUPABASE_URL` 打进了 bundle，域名生效后：

```bash
# 改 .env 里 VITE_SUPABASE_URL 为 https://resume.xnkun.com
docker compose up -d --build
```

## 8. 执行数据库迁移

在自托管 Supabase 的 Postgres 里执行 [supabase/migrations/20260603_commerce.sql](../supabase/migrations/20260603_commerce.sql)（建 users / orders 表 + 触发器 + RLS）。

两种方式任选：

**方式一：容器内 psql（推荐）**

```bash
# 找 db 容器名
docker ps --format '{{.Names}}' | grep -i db
# 假设容器名为 supabase-db-1
docker exec -i supabase-db-1 psql -U postgres -d postgres < supabase/migrations/20260603_commerce.sql
```

**方式二：宿主机 psql（需要数据库密码）**

```bash
sudo apt install -y postgresql-client
PGPASSWORD="上面生成的POSTGRES_PASSWORD" psql -h 127.0.0.1 -p 5432 -U postgres -d postgres -f supabase/migrations/20260603_commerce.sql
```

> ⚠️ `handle_new_user` 触发器在自托管环境同样要求 `SECURITY DEFINER`（迁移文件已含），否则注册会报 `Database error saving new user`。自托管默认无 RLS 干扰，但保留该写法是安全的。

上线前逐项确认：

- [ ] `curl -s https://resume.xnkun.com/api/health` 返回 `{"status":"ok"}`
- [ ] 浏览器访问 `https://resume.xnkun.com` 首页正常加载，URL 路由 `/templates` `/pricing` 可直接打开
- [ ] 注册新账号 → 自动创建 `users` 记录（tier=free），不报 Database error
- [ ] 登录 → 个人中心能看到账号；制作简历能保存（写库成功）
- [ ] 定价 → 选方案 → 支付页能建单（mock 模式 → 点模拟支付 → 订单变 completed、权益到账）

## 11. 微信支付接入

1. 拿到微信支付商户号的 API 私钥与证书，按 [.env.example](../.env.example) 填入壹页简历 `.env` 的 `WECHAT_*` 变量
2. 证书文件放入项目根目录 `./certs/`（docker-compose 已挂载到容器 `/app/certs`）
3. `APP_URL` 必须为已备案的 `https://resume.xnkun.com`
4. 微信商户平台 → 产品中心 → 开发配置，把 `notify_url` 配成 `https://resume.xnkun.com/api/payment/notify/wechat`
5. `.env` 中 `PAYMENT_PROVIDER="wechat"`，重新构建
6. 测试支付一笔，确认回调写入 orders 表（可用 mock 模式对比验证）

> 微信支付要求：**域名已备案** + HTTPS + 服务器可被微信回调服务器访问。这些 §2/§7 已满足。

## 12. 后续产品共用服务器

架构天然支持多产品，二次元拼团平台启动时：

1. 新项目建独立容器，端口错开（`127.0.0.1:3001`）
2. nginx 加一个 `server_name pinzhou.xnkun.com` 站点块，`proxy_pass http://127.0.0.1:3001`
3. 拼团数据库独立：在 Supabase 的 Postgres 里新建 database，或跑独立 Postgres 容器
4. **务必给每个容器加资源限制**（`--memory`），防止拼团秒杀流量挤垮壹页简历：

```yaml
# 拼团容器 docker-compose 片段
services:
  app:
    deploy:
      resources:
        limits:
          memory: 1g
```

5. 各产品独立备份目录、独立 `.env`、独立数据卷

## 13. 常见问题

**Q1：Supabase 镜像拉取超时/极慢**
→ 换 Docker 镜像加速器（§3.3），多备几个轮换；或用轩辕镜像等第三方 pull 后 re-tag。

**Q2：2核4G 内存不足、容器被 OOM 杀掉**
→ 精简 Supabase 去掉 Studio/Realtime/Storage（§5.3）；或升级 2核8G。

**Q3：注册报 `Database error saving new user`**
→ 迁移未执行成功，或 `handle_new_user` 缺 `SECURITY DEFINER`。重跑 §8 迁移。

**Q4：注册后登录提示邮箱未验证**
→ Supabase `.env` 未设 `GOTRUE_MAILER_AUTOCONFIRM=true`（§5.2）。

**Q5：前端改了 `VITE_SUPABASE_URL` 不生效**
→ `VITE_*` 是构建期变量，改完必须 `docker compose up -d --build` 重新构建镜像。

**Q6：微信支付回调失败**
→ 确认域名已备案；确认 `APP_URL`、`notify_url`、证书挂载、`PAYMENT_PROVIDER=wechat`；看服务端日志中微信验签错误。

**Q7：忘记 Supabase 数据库密码**
→ `docker exec -it <db容器名> bash` 进容器用 `psql -U postgres` 直接 `ALTER USER postgres PASSWORD '新密码';` 重置。

**Q8：`SUPABASE_SERVICE_ROLE_KEY` 报「JWT signature does not match」**
→ anon/service_role 必须与 Supabase 的 `JWT_SECRET` 配套生成（§4 用同一 secret 签名），不要混用官方云项目的 key。
