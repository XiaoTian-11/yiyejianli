## 2. 本地开发部署

### 2.1 前置要求

- **Node.js** ≥ 18.0.0（推荐 20.x LTS）
- **npm** ≥ 9.0.0

### 2.2 安装步骤

```powershell
# 1. 克隆项目
git clone <your-repo-url> yiyejianli
cd yiyejianli

# 2. 安装依赖
npm install

# 3. 配置环境变量
# 复制 .env.example 为 .env.local
Copy-Item .env.example .env.local

# 编辑 .env.local，填入你的 DeepSeek API Key
# DEEPSEEK_API_KEY="your-actual-api-key"
```

### 2.3 获取 DeepSeek API Key

1. 访问 [DeepSeek 开放平台](https://platform.deepseek.com/)
2. 注册/登录账号
3. 在「API Keys」页面创建新的 API Key
4. 将 Key 填入 `.env.local` 文件

### 2.4 启动开发服务器

```powershell
npm run dev
```

- 服务端启动在 `http://0.0.0.0:3000`
- Vite 开发中间件提供热重载（HMR）
- 修改源代码后浏览器自动刷新

### 2.5 运行测试

```powershell
# 运行所有测试
npm test

# 或使用 vitest 直接运行
npx vitest run
```

### 2.6 类型检查

```powershell
npm run lint
```

## 3. 生产构建

### 3.1 构建命令

```powershell
npm run build
```

### 3.2 构建过程

```
npm run build 执行以下步骤：

1. vite build
   └─ 编译 React/TypeScript 源码
   └─ Tailwind CSS 处理
   └─ 输出静态文件到 dist/

2. esbuild server.ts --bundle --platform=node --format=cjs
   └─ 将 TypeScript 服务端编译为 CommonJS
   └─ 外部化 node_modules 依赖
   └─ 输出 dist/server.cjs
   └─ 生成 sourcemap: dist/server.cjs.map
```

### 3.3 构建输出

```
dist/
├── index.html             # SPA 入口页面
├── assets/                # 静态资源 (JS, CSS, 图片)
│   ├── index-xxxxx.js
│   └── index-xxxxx.css
├── server.cjs             # 编译后的 Express 服务端
└── server.cjs.map         # 服务端 sourcemap
```

### 3.4 启动生产服务

```powershell
npm start
```

等价于：

```powershell
node dist/server.cjs
```

- 服务端监听 `0.0.0.0:3000`
- 静态文件服务来自 `dist/` 目录
- 所有非 `/api/*` 路由返回 `index.html`（SPA 回退）

## 4. Google AI Studio / Cloud Run 部署

本项目设计为在 Google AI Studio 环境中运行。

### 4.1 AI Studio 部署

1. 在 [AI Studio](https://ai.studio/) 中导入项目
2. 在 Secrets 面板中配置 `DEEPSEEK_API_KEY`
3. AI Studio 自动将应用部署到 Cloud Run
4. 自动注入以下运行时变量：
   - `DEEPSEEK_API_KEY` — 从 Secrets 获取
   - `APP_URL` — Cloud Run 服务 URL
   - `DISABLE_HMR` — 生产环境设为 `true`

### 4.2 手动部署到 Cloud Run

#### 前置要求

- Google Cloud 项目（已启用 Cloud Run 和 Cloud Build API）
- [gcloud CLI](https://cloud.google.com/sdk/docs/install) 已安装并认证

#### 部署步骤

```powershell
# 1. 设置项目
gcloud config set project YOUR_PROJECT_ID

# 2. 构建并推送 Docker 镜像
gcloud builds submit --tag gcr.io/YOUR_PROJECT_ID/yiyue-jianli

# 3. 部署到 Cloud Run
gcloud run deploy yiyue-jianli `
  --image gcr.io/YOUR_PROJECT_ID/yiyue-jianli `
  --platform managed `
  --region asia-east1 `
  --allow-unauthenticated `
  --set-env-vars "DEEPSEEK_API_KEY=YOUR_API_KEY" `
  --port 3000

# 4. 获取服务 URL
gcloud run services describe yiyue-jianli --format='value(status.url)'
```

#### Dockerfile 参考

```dockerfile
# 多阶段构建
FROM node:20-alpine AS builder

WORKDIR /app

# 安装依赖
COPY package*.json ./
RUN npm ci

# 构建
COPY . .
RUN npm run build

# 生产运行阶段
FROM node:20-alpine

WORKDIR /app

# 仅复制生产依赖和构建产物
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./

# 暴露端口
EXPOSE 3000

# 启动服务
CMD ["node", "dist/server.cjs"]
```

### 4.3 Cloud Run 配置建议

| 配置项 | 推荐值 | 说明 |
|--------|------|------|
| **内存** | 512 MiB | 静态文件 + Express 服务 |
| **CPU** | 1 vCPU | 足够处理翻译请求 |
| **最小实例** | 0 | 无请求时缩容到零 |
| **最大实例** | 10 | 峰值并发上限 |
| **并发请求** | 80 | 每实例同时处理请求数 |
| **请求超时** | 300s | 翻译请求可能需要较长时间 |
| **启动健康检查** | `/api/health` | 就绪探针路径 |

## 5. 自托管部署

### 5.1 传统 VPS 部署 (Ubuntu/Debian)

```bash
# 1. 安装 Node.js 20.x
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# 2. 克隆项目
git clone <repo-url> /opt/yiyue-jianli
cd /opt/yiyue-jianli

# 3. 安装依赖并构建
npm ci
npm run build

# 4. 配置环境变量
echo 'DEEPSEEK_API_KEY="your-key"' > .env
echo 'APP_URL="https://your-domain.com"' >> .env

# 5. 使用 PM2 管理进程
npm install -g pm2
pm2 start dist/server.cjs --name yiyue-jianli
pm2 save
pm2 startup
```

### 5.2 Nginx 反向代理

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml image/svg+xml;
    gzip_min_length 256;

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        
        # 延长超时时间（翻译请求）
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

### 5.3 Docker Compose 部署

创建 `docker-compose.yml`：

```yaml
version: '3.8'

services:
  app:
    build: .
    container_name: yiyue-jianli

      - "3000:3000"

      - NODE_ENV=production
      - DEEPSEEK_API_KEY=${DEEPSEEK_API_KEY}
      - APP_URL=${APP_URL}
    volumes:
      - ./logs:/app/logs
    healthcheck:
      test: ["CMD", "wget", "--no-verbose", "--tries=1", "--spider", "http://localhost:3000/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3
```

启动：

```bash
DEEPSEEK_API_KEY="your-key" APP_URL="https://your-domain.com" docker-compose up -d
```

## 6. Firebase 配置

### 6.1 创建 Firebase 项目

1. 访问 [Firebase Console](https://console.firebase.google.com/)
2. 点击「添加项目」
3. 输入项目名称（如 `yiyue-jianli`）
4. 选择是否启用 Google Analytics
5. 创建项目

### 6.2 启用所需服务

在 Firebase Console 中启用：

| 服务 | 路径 | 说明 |
|------|------|------|
| **Authentication** | Build → Authentication | 启用「电子邮件/密码」登录方式 |
| **Cloud Firestore** | Build → Firestore | 创建数据库（选择生产模式或测试模式） |

### 6.3 配置 Firestore 安全规则

将 [firestore.rules](../firestore.rules) 内容部署到 Firebase：

```bash
# 安装 Firebase CLI
npm install -g firebase-tools

# 登录
firebase login

# 初始化（如果还没有 .firebaserc）
firebase init firestore

# 部署规则
firebase deploy --only firestore:rules
```

安全规则内容：

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /resumes/{resumeId} {
      allow read, write: if request.auth != null && request.auth.uid == request.resource.data.userId;
      allow read, delete: if request.auth != null && request.auth.uid == resource.data.userId;
    }
  }
}
```

### 6.4 创建 Firestore 索引

部署 [firebase-blueprint.json](../firebase-blueprint.json) 中定义的索引：

```bash
firebase deploy --only firestore:indexes
```

或通过 Firebase Console 手动创建：

| 集合 | 字段 1 | 字段 2 | 排序 |
|------|--------|--------|------|
| `resumes` | `userId` (ASC) | `updatedAt` (DESC) | 复合索引 |

### 6.5 获取 Firebase 配置

1. 在 Firebase Console → 项目设置 → 常规
2. 找到「您的应用」→ Web 应用
3. 复制配置对象，更新 [firebase-applet-config.json](../firebase-applet-config.json)：

```json
{
  "projectId": "YOUR_PROJECT_ID",
  "appId": "YOUR_APP_ID",
  "apiKey": "YOUR_API_KEY",
  "authDomain": "YOUR_PROJECT.firebaseapp.com",
  "storageBucket": "YOUR_PROJECT.firebasestorage.app",
  "messagingSenderId": "YOUR_SENDER_ID",
  "measurementId": ""
}
```

|------|:---:|------|------|
| `DEEPSEEK_API_KEY` | ✅ | — | DeepSeek API 密钥 |

### 7.2 环境变量文件优先级

```
.env.local          # 本地开发（最高优先级，不提交到 Git）
.env.development    # 开发环境
.env.production     # 生产环境
.env                # 通用默认值（最低优先级）
.env.example        # 配置模板（提交到 Git）
```

### 7.3 安全提醒

- ❌ **永远不要**将 `.env` 文件提交到 Git
- ❌ **永远不要**在客户端代码中硬编码 API 密钥
- ✅ 使用 `.env.example` 作为配置模板
- ✅ 在生产环境中通过平台密钥管理服务注入

## 9. CI/CD 配置

### 9.1 GitHub Actions 示例

创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to Cloud Run

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
      - run: npm ci
      - run: npm test
      - run: npm run lint

  deploy:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - id: 'auth'
        uses: 'google-github-actions/auth@v2'
        with:
          credentials_json: '${{ secrets.GCP_SA_KEY }}'
      
      - name: 'Set up Cloud SDK'
        uses: 'google-github-actions/setup-gcloud@v2'
      
      - name: 'Build and Push'
        run: |
          gcloud builds submit --tag gcr.io/${{ secrets.GCP_PROJECT_ID }}/yiyue-jianli:${{ github.sha }}
      
      - name: 'Deploy to Cloud Run'
        run: |
          gcloud run deploy yiyue-jianli \
            --image gcr.io/${{ secrets.GCP_PROJECT_ID }}/yiyue-jianli:${{ github.sha }} \
            --platform managed \
            --region asia-east1 \
            --allow-unauthenticated \
            --set-env-vars "DEEPSEEK_API_KEY=${{ secrets.DEEPSEEK_API_KEY }}"
```

### 9.2 所需 GitHub Secrets

| Secret | 说明 |
|--------|------|
| `GCP_SA_KEY` | Google Cloud 服务账号 JSON 密钥 |
| `GCP_PROJECT_ID` | Google Cloud 项目 ID |
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥 |
| `FIREBASE_TOKEN` | Firebase CI Token（如需部署 Firestore 规则） |

## 11. 故障排查

### 11.1 常见问题

#### 问题：`DEEPSEEK_API_KEY environment variable is not configured`

**原因：** 环境变量未设置或 `.env` 文件未正确加载。

**解决：**
```powershell
# 检查 .env 文件是否存在
Test-Path .env

# 确认文件内容
Get-Content .env

# 确保变量名正确
# ✅ DEEPSEEK_API_KEY="sk-..."
# ❌ DEEPSEEK_KEY="sk-..."
# ❌ DEEPSEEK=sk-...
```

#### 问题：Firestore 权限错误 (`Missing or insufficient permissions`)

**原因：** 用户未登录，或 Firestore 安全规则阻止了操作。

**解决：**
1. 确认用户已登录
2. 检查 Firestore 安全规则是否正确部署
3. 确认文档中的 `userId` 字段与当前登录用户的 `uid` 一致

#### 问题：`npm run build` 构建失败

**原因：** TypeScript 编译错误或依赖问题。

**解决：**
```powershell
# 清除依赖并重新安装
Remove-Item -Recurse -Force node_modules
Remove-Item -Force package-lock.json
npm install

# 先检查类型错误
npm run lint

# 再次构建
npm run build
```

#### 问题：开发服务器启动后页面无法访问

**解决：**
1. 检查终端输出确认端口号
2. 确认没有其他应用占用 3000 端口：
   ```powershell
   netstat -ano | findstr :3000
   ```
3. 检查防火墙设置

#### 问题：翻译功能返回 500 错误

**原因：** DeepSeek API 调用失败。

**解决：**
1. 检查 `DEEPSEEK_API_KEY` 是否有效
2. 检查 API Key 是否有 DeepSeek API 的访问权限
3. 查看服务端日志获取详细错误信息
4. 检查网络是否能访问 DeepSeek API（api.deepseek.com）
