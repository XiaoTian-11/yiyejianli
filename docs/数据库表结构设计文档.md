## 2. Firestore 集合设计

### 2.1 集合：`resumes`

简历文档集合，每个文档存储一份用户的简历完整数据。

#### 2.1.1 文档路径

```
resumes/{resumeId}
```

- `resumeId`: 字符串，由客户端生成（格式：`{randomId}_{userId}` 或 `default_{userId}`）

#### 2.1.2 文档字段定义

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `userId` | `string` | ✅ | — | 用户 UID（来自 Firebase Auth） |
| `name` | `string` | ✅ | `"未命名简历"` | 简历名称（用户可自定义） |
| `data` | `object` (ResumeData) | ✅ | `INITIAL_DATA` | 简历完整数据对象（详见 §3） |
| `score` | `number` | — | `80` | AI 诊断评分（0–100） |
| `status` | `string` | — | `"new"` | 简历状态：`"new"` / `"draft"` / `"completed"` |
| `templateId` | `string` | — | `"modern"` | 当前使用的模板 ID（见模板表） |
| `updatedAt` | `timestamp` | — | `serverTimestamp()` | 最后更新时间（Firestore 服务端时间戳） |

## 3. 核心数据结构定义

### 3.1 ResumeData（简历完整数据）

```typescript
interface ResumeData {
  personalInfo: PersonalInfo;       // 个人信息
  summary: string;                  // 自我评价（主语言）
  summary_secondary?: string;       // 自我评价（副语言）
  experience: Experience[];         // 工作经历列表
  education: Education[];           // 教育背景列表
  skills: string[];                 // 技能列表（主语言）
  skills_secondary?: string[];      // 技能列表（副语言）
  projects: Project[];              // 项目经历列表
  customSections?: CustomSection[]; // 自定义板块
  sections: ResumeSection[];        // 板块排序/可见性配置
  primaryLanguage?: string;         // 主语言代码，如 "zh"
  secondaryLanguage?: string;       // 副语言代码，如 "en"
  displayMode?: 'primary' | 'secondary' | 'bilingual'; // 显示模式
}
```

## 4. Firestore 安全规则

### 4.1 当前规则

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /resumes/{resumeId} {
      // 写入：仅允许已认证用户，并且请求数据中的 userId 与当前用户 UID 一致
      allow read, write: if request.auth != null 
                          && request.auth.uid == request.resource.data.userId;
      
      // 读取/删除：仅允许已认证用户，并且已有文档中的 userId 与当前用户 UID 一致
      allow read, delete: if request.auth != null 
                           && request.auth.uid == resource.data.userId;
    }
  }
}
```

### 4.2 权限矩阵

| 操作 | guest（未登录） | free（已登录） | member（会员） |
|------|:---:|:---:|:---:|
| 读取自己的简历 | ❌ | ✅ | ✅ |
| 创建简历 | ❌ | ✅ | ✅ |
| 更新简历 | ❌ | ✅ | ✅ |
| 删除简历 | ❌ | ✅ | ✅ |
| 读取他人简历 | ❌ | ❌ | ❌ |

> **注意:** 未登录用户（guest）和演示用户使用 `localStorage` 存储数据，不经过 Firestore。

## 5. 索引设计

### 5.1 复合索引

| 索引名称 | 集合 | 字段 | 排序 | 用途 |
|----------|------|------|------|------|
| `userId_updatedAt` | `resumes` | `userId` | ASC | 按用户查询简历列表 |
| | | `updatedAt` | DESC | 按更新时间倒序排列 |

### 5.2 Firestore 索引配置 (firebase-blueprint.json)

```json
{
  "collections": {
    "resumes": {
      "indexes": [
        {
          "fields": [
            { "field": "userId", "order": "ASCENDING" },
            { "field": "updatedAt", "order": "DESCENDING" }
          ]
        }
      ]
    }
  }
}
```

### 5.3 建议补充索引（如需扩展）

| 索引 | 用途 |
|------|------|
| `status + userId` | 按状态筛选用户简历 |
| `templateId + userId` | 按模板筛选用户简历 |

## 7. 数据迁移策略

### 7.1 旧版数据兼容

系统在 `firebaseService.ts` 中实现了旧版数据自动迁移：

1. **旧版路径检测：** 当 `resumes` 集合中按 `userId` 查询无结果时，检查旧版路径 `resumes/{userId}`（即文档 ID 等于 userId 的旧格式）
2. **自动迁移：** 如果发现旧版文档，自动将其字段规范化后写回同一文档路径
3. **默认创建：** 如果完全无数据，自动创建包含默认简历数据的新文档（ID 格式：`default_{userId}`）

### 7.2 迁移流程

```
查询 resumes (WHERE userId == X)
     │
     ├─ 有结果 → 返回列表（按 updatedAt 倒序）
     │
     └─ 无结果 → 检查旧版 resumes/{userId}
                    │
                    ├─ 存在 → 规范化后写回，返回旧数据
                    │
                    └─ 不存在 → 创建默认简历，返回默认数据
```
