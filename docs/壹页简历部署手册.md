## 2. 部署前检查

在项目根目录执行：

```bash
cd d:\File\AI\cursor\jianli_Project\yiyejianli

git status
git log -1 --oneline
npm test
npx tsc --noEmit
```

若有需要上线的代码，先提交并推送：

```bash
git add -A
git commit -m "描述本次改动"
git push origin master
```

不要把 `.env`、私钥或 API 密钥提交到 Git。服务器自己的 `/var/www/yiyejianli/.env` 由服务器维护，完整部署脚本会排除本地 `.env`，不会覆盖线上配置。

## 3. 主站完整部署（推荐）

适用于主站前端、模板、支付、服务端接口等改动：

```bash
cd d:\File\AI\cursor\jianli_Project\yiyejianli
bash deploy/resume/deploy.sh gutuanbao-server root
```

也可以用服务器 IP：

```bash
bash deploy/resume/deploy.sh 139.224.196.26 root
```

脚本流程：

1. 本机构建 `dist/`、`dist/admin/` 和 `dist/server.cjs`
2. 上传源码、构建产物和部署配置（排除 `node_modules`、`.env`）
3. 服务器执行 `npm ci --omit=dev`
4. `pm2 restart yiyejianli` 并保存 PM2 进程表
5. 请求服务器本机 `http://127.0.0.1:3001/api/health`

**重要**：不要在 2 核 2G 服务器上直接构建 Vite；部署脚本设计为本机构建后上传，避免服务器内存不足。

## 4. 只部署管理后台

仅修改管理后台 UI 或后台接口、且不希望重新覆盖主站前端时使用：

```bash
bash deploy/resume/deploy-admin.sh gutuanbao-server root
```

该脚本只上传 `dist/server.cjs` 和 `dist/admin/**`，不上传主站 `dist/`。后台子域名首次配置需参考 [admin-resume.conf](../deploy/resume/admin-resume.conf)。

## 5. 数据库迁移

部署脚本**只上传 SQL 文件，不会自动执行 Supabase migration**。执行迁移前：

1. 打开 Supabase 项目的 SQL Editor
2. 检查目标 SQL 是否未执行
3. 按顺序粘贴执行 `supabase/migrations/` 中新增的 SQL
4. 在 Supabase Table Editor 或 API 中验证字段/表

执行涉及用户、订单、支付字段的迁移前，先备份并确认线上 `.env` 使用的是同一个 Supabase 项目。

## 7. 常见故障

### SSH `Connection reset`

通常是瞬时网络抖动。先重新测试：

```bash
ssh -o ConnectTimeout=8 gutuanbao-server "echo SSH_OK"
```

确认恢复后重新执行部署脚本。若服务器目录出现半包，脚本重跑会覆盖完整文件。

### PM2 重启后 API 不健康

```bash
ssh gutuanbao-server "pm2 logs yiyejianli --lines 100 --nostream"
ssh gutuanbao-server "cd /var/www/yiyejianli && pm2 restart yiyejianli"
ssh gutuanbao-server "curl -s http://127.0.0.1:3001/api/health"
```

微信支付模式启动需要服务器具备 `certs/apiclient_key.pem` 和 `certs/wechatpay_pub.pem`，缺少微信支付公钥会导致真实支付模式启动失败；本地调试可使用 `PAYMENT_PROVIDER=mock`。

### HTTPS 返回谷团宝内容或证书异常

不要直接用只含 80 块的 Nginx 配置覆盖线上完整配置。检查：

```bash
ssh gutuanbao-server "nginx -T 2>/dev/null | grep -A 15 -B 3 'resume.xnkun.com'"
```

若 certbot 注入的 443 server 块被覆盖，先恢复站点配置并执行：

```bash
ssh gutuanbao-server "certbot --nginx -d resume.xnkun.com --redirect"
ssh gutuanbao-server "nginx -t && systemctl reload nginx"
```

### 端口冲突

共享服务器上谷团宝和壹页简历共存。壹页简历 PM2 使用 3001，不要改到谷团宝正在使用的端口。后台本地端口若与其他 Vite 项目冲突，修改 `admin/vite.config.ts` 的 `server.port`（常用 5175）。

### 模板中心点击后没有进入编辑器

正确流程是：点卡片打开预览 → 点预览弹窗里的「立即使用此模板」。如果未登录，登录成功后应自动跳 `/builder`。该跳转依赖 `App.tsx` 的 `pendingTemplateId` 和 `handlePostLoginJump`；改动后需重点回归此流程。

## 8. 回滚

先查看远程备份/当前提交，再决定回滚，不要盲目 `reset --hard`：

```bash
ssh gutuanbao-server "cd /var/www/yiyejianli && pm2 status && ls -lt dist | head"
```

Git 版本回滚的一般方式是在本地恢复到已知正确提交、重新构建并运行完整部署脚本。回滚前确认数据库迁移通常不可逆，应用代码回滚不等于数据库回滚。
